# `sentiment_score` 계약 (2026-09-16 패널 · 사장님 D2 승인)

## 핵심 계약
**`sentiment_score` 는 연속값이 아니다.** 부호(±) 신호로만 쓸 것.

## 근거 (코드 실측)
- `news_scraper/sentiment_analyzer.py:305-308` 의 비율식은 정수 카운트 위에서
  `p > n ⇒ p ≥ n+1 ⇒ p/(n+1) ≥ 1` 이 항상 성립해 **정확히 ±1.0 으로 포화**된다.
  즉 `calculate_sentiment_score` 자체의 치역은 `{-1, 0, +1}` 세 값뿐이다(E1, E5 재검산).
- 따라서 `:314-318` 의 ±0.5 fallback 은 **도달 불가능한 죽은 코드**다.
- 최종 컬럼값은 `:464-466` 의 `0.7·title + 0.3·content` 가중 + STRONG 키워드 ±0.3 보정으로만
  생기므로, 실제 치역은 **11값 격자 `{0, ±0.3, ±0.4, ±0.6, ±0.7, ±1}`** 이다.
  국내 4소스(naver/dart/hankyung/mk) 7일 10,049행의 **99.99%** 가 이 격자 위에 있다(E1, E5 검산).
- **점수 크기는 본문 길이의 함수다** — hankyung 동일 소스 내 본문 있음 |점수| 평균 0.3173,
  본문 없음 0.0605(5.2배 차)(E1 F2). 크롤 성공 여부가 극성 크기로 둔갑한다.
- 영어 분석기는 다른 척도다 — `english_sentiment_analyzer.py:184` 는 `(p−n)/total` 연속식이라
  같은 `sentiment_score` 컬럼에 **한국어(11값 격자)와 영어(연속) 두 척도가 혼재**한다(E1).

## 소비자 지침
- **쓸 것**: 부호(양/음/0) 신호로만 사용.
- **쓰지 말 것**: 연속 통계(IC, 회귀계수, 상관 등) 직접 투입 — 분해능 11값(3값×가중)뿐이라
  통계적 의미가 없다. 소스 간 점수 크기 비교도 금지(0점 비율 dart 87.8% 대 mk 6.7%,
  BRIEF 실측 — 크기 차이는 신호가 아니라 소스별 본문 캡처율 차이다).

## 변경 금지 조항
